# Template format

A template is a TOML file with three sections: an optional `[info]` block,
an optional `[options]` block, and one or more `[[files]]` entries.

```toml
[info]
name = "Template Name"
description = "What this template builds"
author = "Your Name"

[options]
git = false
project_root = "{{$PROJECTNAME}}"
use_liquid = false

[[files]]
path = "file1.txt"
content = """
Content of file 1
"""

[[files]]
path = "file2.txt"
content = """
Content of file 2
"""
```

## `[info]`

Optional metadata describing the template. `name`, `description`, and `author`
are shown by `spark list`. You can add any other keys for your own reference
(for example a `reference` URL) — Spark ignores extra fields.

The `[info]` values are also exposed back to the template as placeholders; see
[metadata placeholders](#metadata-placeholders) below.

## `[options]`

Settings that control generation.

| Option | Description | Example |
|---|---|---|
| `git` | Initialize a Git repository in the project directory. | `git = true` |
| `project_root` | The project directory. A constant, or `{{$PROJECTNAME}}` to prompt. | `project_root = "{{$PROJECTNAME}}"` |
| `use_liquid` | Enable [Liquid templating](liquid.md). Off by default. | `use_liquid = true` |
| `json_data` | Embed JSON for `{{$.…}}` lookups. See [JSON data](json.md). | *(a table)* |

## `[[files]]`

Each `[[files]]` entry is one output. `path` is where it goes and `content` is
what it contains; both are rendered. An entry can also carry a
[`mode`](write-modes.md) to merge into an existing file instead of overwriting
it.

```toml
[[files]]
path = "src/main.rs"
content = "fn main() {}"
```

`path` is normally a filesystem location, but a scheme prefix can redirect it to
`stdout`, `stderr`, or the clipboard — see [Output targets](output-targets.md).

## Placeholder format

Use `{{$NAME}}` for a value to substitute. Placeholders work in both `content`
and `path`, so file and directory names can be dynamic.

```toml
[[files]]
path = "{{$PROJECTNAME}}/README.md"
content = "# {{$PROJECTNAME}}"
```

Where values come from, and the built-in names, are covered in
[Placeholders and functions](placeholders.md) and
[Supplying values](values.md).

## Metadata placeholders

A template's own `[info]` and `[options]` values are available to its files,
paths, and anchors as placeholders:

| Placeholder | Source | Example |
|---|---|---|
| `INFO_NAME` | `[info] name` | `demo` |
| `INFO_AUTHOR` | `[info] author` | `pwnxpl0it` |
| `INFO_DESCRIPTION` | `[info] description` | `a demo template` |
| `OPTIONS_GIT` | `[options] git` as `true`/`false` | `true` |
| `OPTIONS_USE_LIQUID` | effective `use_liquid` | `false` |

`INFO_*` tokens appear only when the matching field is set. A supplied value of
the same name (environment variable, config keyword, or `--from`) takes
precedence over the template's own metadata.

```toml
[info]
name = "demo"
author = "pwnxpl0it"

[[files]]
path = "README.md"
content = "# {{$INFO_NAME}}\n\nGenerated by {{$INFO_AUTHOR}} on {{$YYYY}}."
```

When Liquid is enabled, the same values are also available as the `info` and
`options` objects; see [Liquid templating](liquid.md).

## Escaping a placeholder

To emit a literal `{{$NAME}}` in the output, double the dollar sign. `{{$$NAME}}`
is never resolved and is written out as `{{$NAME}}`. `spark init` applies this
escape automatically to any captured file that already contains
placeholder-like text.
